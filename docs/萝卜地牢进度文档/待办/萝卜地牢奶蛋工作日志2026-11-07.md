## 二、本次踩的坑（重要，别再踩）

1. **未绑定键进不了输入管线（V 一直没反应的最终真凶）**
   - `InputHandler.keyDown` 只放行 `KeyBindings.isKeyBound(keyCode)==true` 的键。
   - C 在默认键位表（`SPDAction` 绑 TAG_LOOT）所以一直可达；V 不在任何表 → 事件根本不产生，任何 `KeyEvent` 监听器都收不到（日志里连一行都打不出）。
   - **修法**：`SPDAction` static 块加 `KeyBindings.addHardBinding( Input.Keys.V, SPDAction.NONE )`（同 ALT_RIGHT/ENTER 全屏键惯例；NONE = 无按钮可抢）。
   - 给自定义快捷键加键时，**必须同时检查 SPDAction 绑定表**，只写 KeyEvent 监听器是不够的。

2. **弹道坐标 vs 格索引的两套约定**
   - 弹道路径点 `(cx,cy)` 就是格 `(cx,cy)` 的**中心**（`cellToWorld` 才 +0.5 换算像素）。
   - 曾在 `heroCellCenter()` 里错加 +0.5，判定点偏 0.707 格 > `CONTACT_DIST` 0.65 → 永远擦肩而过走兜底（日志 `fallback=true`）。已改为不加 0.5。
   - 接触判定用**世界坐标距离 ≤0.65 格**（`pathPointAt(t)` 对英雄格中心），不用格相等比较——贴角路径逐帧取整会漏格。

3. **patch 工具对大段 Java 的模糊匹配会弄乱缩进/作用域**（`simulate` 抽取时把形参引用也搞错了）。多文件结构性重构优先整文件 `write_file` 重写。

4. **离线模拟要镜像真实代码的全部约定**：接触重放一开始瞄的和判的都是同一点，测不出坐标错位——"模拟过了"不等于"实机过了"，坐标类修复必须实机复核。

5. 验证脚本自身判据错了三次（子串匹配、内部类 `$1` 路径、未把新文件加白名单）：**FAIL 先怀疑判据再怀疑产品代码**，但要拿证据（如直接 `zipfile` 拆 jar 看字节）。
