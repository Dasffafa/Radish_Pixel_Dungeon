# 09 常见坑与排查

按「症状 → 先查什么」排。每一条都是这个仓库真实踩过的。

## 游戏卡住 / 回合无限空转

- 远程怪：`Mob` 发了投射物却没有 `onZapComplete()` 回调 → `Actor.process()` 永远等完成。
- 检查该 `act()` 是否每条分支都 `spend()` 或 `next()`。

## `!!!NO TEXT FOUND!!!`

1. 键名写错（包路径/大小写/内部类 `$`）——去同类条目抄；
2. 英文侧没写（英文界面必现）；
3. `actionName()` 的键是 `"ac_" + action`，大小写要和常量一致（`ac_GIVE`）。

## 贴图错位 / 只有半张脸

- 图集尺寸必须能被帧宽高整除：`200×64` 用 `12×15` 切会错行，要裁成 `120×45`；
- 帧索引 = `行号 × 每行列数 + 帧号`，改布局后索引必须同步；
- `assets/sprites/` 下的单图改名后，`Assets.java` 常量也要改。

## 读档崩溃 / 属性丢失

- 改类名要补 `Bundle.addAlias()`；
- 新字段先 `bundle.contains(key)` 再读，给默认值；
- `restoreFromBundle` 里访问 `Dungeon.level`/`Dungeon.hero` 会 NPE（还没就绪）。

## 启动就崩（Android）

- 日志出现 `FirebaseInitProvider` → 没有有效 `google-services.json`，按 [03](03-构建与打包.md) 临时移除 Firebase。

## 模拟器里 UI 不显示 / 点不动

- 先确认 UI 是否要「捡起说明书」之类的前置才展开；
- 分辨率与 density 组合极端（1080×2340@320）时 UI 相机会算得很扁 → 换成 1080×1920@320 再看；
- 用 `adb shell wm size / wm density` 调，别改代码去迁就模拟器。

## 背包/容器滚动异常

见 [07](07-UI与背包.md) 的两个坑：`controller` 没铺满、`PointerArea` 吞 DOWN。

## 通用排查顺序

1. `./gradlew :core:compileJava` —— 编译过不过
2. `adb logcat | grep -i "AndroidRuntime\|GAME"` —— 有没有异常栈
3. 真机/模拟器复现一次，截图留证
4. 再回代码看逻辑
