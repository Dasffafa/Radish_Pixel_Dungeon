# 02 架构总览

> 更细的图与类表见 `docs/萝卜地牢开发文档/spd-architecture-overview.md`。

## 模块

```
SPD-classes   ← 引擎公共层（noosa UI/Gizmo、通用工具、日志），无游戏内容
core          ← 游戏本体（1777 个 java）：actors / levels / items / scenes / ui / windows …
  ├ android   ← Android 壳（Activity、manifest、资源打包）
  ├ desktop   ← 桌面壳（LWJGL）
  ├ services  ← 更新/新闻/分析等可选服务
  └ event-processor ← 注解处理器（构建期码生成）
```

`core` 依赖 `SPD-classes`；两个壳都依赖 `core`。**改游戏逻辑几乎都在 `core`**。

## core 里的分层

| 层 | 包 | 说明 |
|---|---|---|
| 场景 | `scenes` | `TitleScene / HeroSelectScene / InterlevelScene / GameScene`，一屏一 Scene |
| 关卡 | `levels` | `Level` 子类（每层一个）、`Terrain`、`Painter`、分支 `Branches` |
| 角色 | `actors` | `Char → Hero / Mob`；`buffs`、`blobs`（特效）、`mobs`（含 `npcs/`） |
| 物品 | `items` | `Item → …`，武器/护甲/药水/法杖/神器/护甲技能 |
| 界面 | `ui` / `windows` | 常驻控件 vs 弹出窗口 |
| 渲染 | `sprites` | 每个 Char 一个 `CharSprite`，动画帧在贴图里切 |

## 一条改动要碰的典型链路

新增一只怪（例如「哥布林骑手」）：

```
actors/mobs/XxxMob.java        ← 属性/行为（HP、伤害、AI）
sprites/XxxSprite.java         ← 贴图与动画（帧号）
assets/sprites/xxx.png         ← 素材
Assets.java                    ← 贴图路径常量
messages/actors/actors*.properties ← 名字/描述
levels/…/createMobs() 或 Generator ← 生成规则
```

四条缺一条就会出问题（尤其贴图常量与文本键）。

## 引擎层要点（noosa）

- 所有可见物是 `Gizmo` 树上的节点，`Scene.add()` 才参与渲染与 `update()`。
- `Actor.process()` 驱动回合队列：**Mob 的 `act()` 里必须调用 `spend()` 或 `next()`**，否则整个游戏卡住（见 [04](04-生物与Boss.md)）。
- `Camera` 决定视口；`PixelScene.uiCamera` 是 UI 层相机，改 UI 缩放/布局时动它。

## 存档

- 类名即键：改类名必须补 `Bundle.addAlias()`，否则读档 NPE。
- 新字段一律按「旧档无此键」防御（`bundle.contains(key)` 再读）。
