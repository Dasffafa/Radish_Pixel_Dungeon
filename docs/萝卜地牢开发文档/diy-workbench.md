# DIY 工作台（拆解 / 自由组装）

> 状态：**已实现**。只在「智能怪物」挑战开局送一件，其它途径无法获得。

## 一句话

拆任何非唯一物品 → 拿材料；然后**想加什么就加什么**（任意等级、任意附魔/铭文、任意特性、任意伤害/减伤），只要材料够。

## 拆解产出（`Diy.analyze`）

| 产出 | 条件 | 数量 |
|---|---|---|
| 铁件 | 武器/护甲/投掷物 | `2 × 阶位 + 1` |
| 魔尘 | 法杖/戒指/神器/饰品/药剂/卷轴/法术/符石 | `2 × 阶位`（法杖戒指神器按 3 阶） |
| 杂料 | 食物、炸弹等 | `1` |
| **强化精华** | 物品每有 1 级 | `max(0, level)` |
| **附魔精粹** | 身上每一个附魔（武器）/ 铭文（护甲） | 每个 1，记住具体是哪个 |
| **特性精粹** | 白帝圣剑 / 前线旗 / 莫雷洛秘典 / 拉莱耶文本 / 幻影之书 / 大太刀 | 每个 1，记住特性 id |

DIY 贴上去的附魔/铭文/特性，拆解时会原样还回来；强化等级不计入基础材料，只变成强化精华。

## 组装：全开放，材料说话

选底材（任意分类里的任意物品）之后进入 `WndDiyAssemble`，四块都能改：

| 想加什么 | 怎么选 | 价格 |
|---|---|---|
| **等级** | `－1 / ＋1 / ＋5 / 清零`，上限就是手头的强化精华 | 每级 1 份强化精华 |
| **附魔 / 铭文** | 点「选择附魔」进 `WndDiyPick`，列表是游戏里的**全部**附魔（武器 60 种、护甲 30 种，含诅咒），可多选、可全选、可清空 | 有对应精粹 → 精粹×1；没有 → 魔尘×4 |
| **效果** | 点「选择效果」，163 条按来源分组；**装备后生效、脱下消失** | **必须有对应效果精粹（精粹×1），不能用材料代替** |
| **属性** | 武器：伤害 `＋1/＋5`；护甲：减伤 `＋1/＋5`；`清零` | 每点 铁件×2 |

底部实时显示这次要付的账（`需要：铁件×N　魔尘×N　强化精华×N　XX精粹×1`），付不起时按钮是灰的、字变红。
底材本身的材料价（`拆解产出 × 1.5`）也计入总价。

- 伤害加成写进 `KindOfWeapon.fusionMin/fusionMax` → 真实参与 `min()/max()`；
  这两个字段以前没有存档，本功能顺手补上了（`kw_diy_min/max`），DIY 加的伤害读档不会丢。
- 减伤加成写进 `Armor.fusionDRMin/fusionDRMax` → 真实参与 `DRMin()/DRMax()`。
- 附魔/特性/属性都可以同时叠任意多个，没有数量上限。

## 组装界面：四栏结构

组装窗口按顺序分四栏，和游戏里其他合成界面一致：

1. **等级**：强化精华，每份 +1 级，上限 = 背包里的强化精华数量。**只有可强化物品（装备）才有这一栏**；
   药水/卷轴/符石/食物不显示等级、不吃强化精华（`Item.isUpgradable()` 判定）。
2. **附魔**：全游戏 60 种武器附魔 / 30 种护甲铭文，想选多少选多少；有精粹用精粹，没有花魔尘。
3. **效果**：共 163 条，按来源分组（装备/药水/卷轴/法杖/投掷物/护甲/符石/消耗品 + 武器附魔/护甲铭文）；
   **装备后生效、脱下消失**。
4. **属性**：武器有伤害 / 攻击距离 / 攻击速度；护甲只有减伤。

### 属性怎么算

| 属性 | 花费 | 效果 |
|---|---|---|
| 伤害 | 铁件 ×2/点 | 写进 `fusionMin/fusionMax`（已有存档） |
| 攻击距离 | 铁件 ×3/点 | `Weapon.RCH += 点`（这次补了 `diy_rch` 存档） |
| 攻击速度 | 铁件 ×4/点 | `Weapon.DLY -= 0.05/点`，最低 0.4（这次补了 `diy_dly` 存档） |
| 减伤 | 铁件 ×2/点 | 写进 `fusionDRMin/fusionDRMax`（已有存档） |

`RCH`/`DLY` 原来不存档，改完武器读档会丢，所以这次一并加进了 `Weapon.store/restoreFromBundle`。

**效果名字**：`Diy.effectName` / `Diy.passiveName` 对物品效果（`item:` 前缀）和附魔效果（`e:` 前缀）都做了中文名映射，
物品描述、拆解产物、精粹名字都不会出现裸 id。

### 附魔/特性只能用精粹

从这版开始，**附魔和特性/效果不能再拿铁件/魔尘顶替**，必须用对应的精粹：
- 附魔精粹：拆解带该附魔/铭文的装备获得
- 效果精粹：拆解带该特性/效果的装备获得（物品类效果也一样，如「火焰弹」效果精粹）

选择器里没有精粹的条目会显示「精粹×1（缺）」，仍然可以选，但组装时会因为
`price.affordable == false` 被拒绝，不会扣任何材料。这样「拆解 → 攒精粹 → 重新组装」
才是唯一的获取途径。

### 拆料和精粹都存在工作台里，不占背包

拆解产出的一切（铁件 / 魔尘 / 杂料 / 强化精华 / 附魔精粹 / 效果精粹）都不再作为实体物品塞进背包，
而是记在工作台自带的仓库里（`DiyWorkbench.materials` + `DiyWorkbench.essences`，随工作台一起存档）：

- 拆解时直接进工作台仓库，日志里的「→ …」就是进仓库
- 组装时直接从仓库扣
- 旧版本遗留的背包材料/精粹会在第一次查询时自动搬进工作台（`absorbLooseMaterials` / `absorbLooseEssences`）
- 如果身上没有工作台，才退回旧行为把材料/精粹作为物品发放，避免丢东西
- 「查看精粹」窗口现在叫「工作台仓库」：顶部汇总材料 + 三类精粹，下面按分组列出具体条目

这样背包不会再被几十种精粹塞满，工作台本身就是一个「精粹容器」。

### 手机版适配

窗口宽度统一到游戏常用的手机尺寸（竖屏 120 / 横屏 144 UI 像素，和 `WndOptions` 一致），
并且所有 DIY 窗口的高度都限制在 UI 视口内：

- 「组装」最多占 80% 视口高度，价格行和「开始组装」按钮永远可见
- 「选择附魔/效果」「工作台仓库」「底材列表」最多占 72%，其余交给滚动条
- 「DIY 合成」分类按钮改成 3 列，17 个分类在两屏内排完
- 标题、价格、按钮位置都按实际视口高度算，不再依赖 0.55 倍屏高的经验值

这样在手机上不会出现窗口比屏幕还高、按钮被底部 HUD 挡住的情况。

### 查看精粹

工作台物品菜单里新增「查看精粹」：打开 `WndDiyEssence`，按分组列出仓库里的东西：

- 顶部汇总：强化 / 附魔 / 效果精粹各多少份
- 强化精华
- 附魔精粹：按名字排序，只列持有量 > 0 的
- 效果精粹：按来源分组（装备 / 药水 / 卷轴 / 法杖 / 消耗品 / 投掷物 / 护甲 / 符石），
  每行「名字精粹 ×数量」

窗口只读，关闭按钮退出；数据直接读工作台仓库，不占背包格子。

### 效果精粹怎么拿

`附魔/特性只能用精粹` 之后，所有效果精粹都必须能正常获得。除了拆解带该附魔/特性的装备之外，
**拆解任意物品还会额外掉 1 个「同类来源」的随机效果精粹**：

| 拆的物品种类 | 掉的效果精粹来源 |
|---|---|
| 药水 | 药水 |
| 食物 / 戒指 / 神器 / 饰品 | 消耗品 |
| 卷轴 | 卷轴 |
| 符石 | 符石 |
| 炸弹 / 投掷武器 | 投掷物 |
| 法杖 | 法杖 |
| 护甲 | 护甲 |
| 武器 | 装备（白帝/前线旗/大太刀特性） |

日志会写「拆解：xxx → …（额外冷静精粹×1）」。这样截图里那种
「冷静/大太刀/盈能法杖/魔能透视/戒指强化」精粹都能靠拆解对应类别物品攒出来，
不再有永远拿不到的条目。

### 消耗品专属属性

药水/卷轴/符石/食物/炸弹这类不可强化物品没有伤害/减伤，但有自己的一套属性：

| 属性 | 适用 | 花费 | 效果 |
|---|---|---|---|
| 数量 | 所有可堆叠物品 | 铁件 ×2/点 | 成品数量 1 + 点数（一次做 3 瓶药水） |
| 饱食度 | 食物 | 铁件 ×2/点 | 每个 +50 能量 |
| 充能 | 法杖 | 铁件 ×3/点 | 初始充能和上限 +点数 |

组装窗口会根据底材自动只显示适用的那几行（药水显示数量、口粮显示数量+饱食度、法杖显示充能），
等级栏和附魔/效果栏对这些物品本来就不适用，也会自动隐藏。

**物品效果怎么触发**：`DiyItemPulse` 在装备后 **8 回合内第一次触发**，之后每 **30 回合**一次；日志会提示「物品效果：火焰弹 → 目标」。执行的是真实逻辑——
药水走 `Potion.drink`、卷轴走 `doRead`、炸弹对最近敌人 `explode`、符石对最近敌人 `activate`
（都依赖 `Item.curUser/curItem`，已统一设置）。所以「治疗药水」效果就是周期性真的喝一瓶治疗药水。

**周期脉冲**：临时型 buff 会自己 detach，`DiyEffectsTracker` 每 20 回合检查一遍，
装备还穿着就补挂，让「治疗/饱食/树肤」这类变成周期性生效。

**附魔/铭文条目**：效果栏里也能直接选附魔和铭文，选中的会并进 `diyEnchants`；
和「2. 附魔」栏重复，但两边选的是同一个集合，不会重复扣材料。给武器选铭文、
给护甲选附魔会在组装时被拒绝并提示。

## 多附魔怎么生效

`Item.diyEnchants`（存档键 `diy_enchants`）记录贴上去的全部附魔/铭文类名，运行时实例化后逐个触发：

- `Weapon.diyEnchantments()` → `Weapon.proc()` / `Weapon.modifyDamageInfo()` 每次都把全部附魔跑一遍。
- `Armor.diyGlyphs()` → `Armor.proc()` 每次都把全部铭文跑一遍，并给每个铭文注入 `armor` 字段。
- 面板由 `Item.withFusedInfo` 追加「DIY 附魔：」「DIY 特性：」。

限制：DIY 附魔覆盖 `proc` 与 `modifyDamageInfo` 两类钩子，不参与面板数值
（`panelDamageMultiplier`）、`releasesConservedDamage` 和 `IDamageModifier` 管线注册。

## 贴图

16×16，全部由 `tools/diy_sprites.py` 生成（`--preview 路径` 出对照图）：

| 资源 ID | 用在哪 |
|---|---|
| `diy_metal` / `diy_arcane` / `diy_scrap` / `diy_essence_level` / `diy_workbench` | 材料、强化精华、工作台（手绘） |
| `diy_passive_eye` / `_flag` / `_cabala` / `_rlyeh` / `_shadow` / `_taijutsu` | 6 种武器特性精粹 |
| `diy_effect_<id>` | 13 种常驻效果精粹（四角星光点，按 id 稳定取色） |
| `diy_enchant_<snake_case>` | 每个武器附魔/诅咒（如 `diy_enchant_blazing`） |
| `diy_glyph_<snake_case>` | 每个护甲铭文/诅咒（六边形护符） |
| `diy_essence_enchant` / `diy_essence_passive` | 认不出 payload 时的兜底 |

精粹贴图名由 `Diy.enchantSprite(clsName)` / `Diy.passiveSprite(id)` 按类名算。
脚本扫描 `items/weapon/enchantments`、`items/weapon/curses`、`items/armor/glyphs`、`items/armor/curses`，
**新增附魔/铭文后要重跑**：

```bash
python tools/diy_sprites.py
./gradlew generateRuntimeAtlasManifests
```

## 数据 / 文件

- `DiyComponent`：可堆叠部件，`kind = LEVEL / ENCHANT / PASSIVE`，`payload` 存附魔类名或特性 id。
- `Item.diyPassives` / `Item.diyEnchants`：字符串列表，存档键 `diy_passives` / `diy_enchants`。
- 特性 id → 效果（`Diy.applyPassive`）：`eye` 白帝独眼、`flag` 前线旗预警、`cabala` 莫雷洛、
  `rlyeh` 拉莱耶、`shadow` 幻影之书、`taijutsu` 大太刀（冷静 + 暴击）。
- 全附魔目录：`Weapon.Enchantment.common/uncommon/rare/curses` + `EXTRA_WEAPON_ENCHANTS`；
  护甲铭文：`Armor.Glyph.common/uncommon/rare/curses`。

| 文件 | 作用 |
|---|---|
| `items/DiyWorkbench.java` | 物品本体、拆解选物品窗口（先预览产出） |
| `items/DiyMaterial.java` | 基础材料 |
| `items/DiyComponent.java` | 组件（强化精华/附魔精粹/特性精粹，带 payload，按 payload 换贴图） |
| `items/Diy.java` | 拆解产出、全附魔目录、计价、组装 |
| `items/Item.java` | `diyPassives` / `diyEnchants` 字段、存档、描述 |
| `items/KindOfWeapon.java` | 伤害加成字段的存档（`kw_fusion_min/max`） |
| `items/weapon/Weapon.java`、`items/armor/Armor.java` | 多附魔/多铭文的 proc 链 |
| `windows/WndDiyCraft.java` / `WndDiyCraftList.java` | 分类 → 底材 |
| `windows/WndDiyAssemble.java` | 组装主窗口（等级/附魔/特性/属性/总价） |
| `windows/WndDiyPick.java` | 全附魔 / 全特性列表（多选、全选、清空） |
| `tools/diy_sprites.py` | 贴图生成器 |

## 不能拆 / 不能合的东西

`Diy.canDismantle` 挡掉：工作台自己、材料、部件、背包、钥匙、金币、`unique` 唯一物品、
以及挂在装备栏里的东西（含备用武器、额外戒指位、投掷位）。
组装列表不开放 `unique` 物品、挑战禁用的力量药水/升级卷轴、测试模式物品。

## 获取

- **只在「智能怪物」挑战（`Challenges.REAL_INTELLIGENCE`）开局发放**：
  `Dungeon.newGame()` 里 `GamesInProgress.selectedClass.initHero(hero)` 之后，
  如果 `Diy.shouldGrantStarterWorkbench()` 为真才塞进背包。
- 商店不再补货（`ShopRoom.generateItems()` 里原补货逻辑已删除），
  普通模式、掉落、商店、红包等其它途径都拿不到工作台。
- 因此普通模式完全不会出现 DIY 内容；想玩 DIY 请开「智能怪物」挑战。

## 融合系统已删除

本分支原来的装备融合（`Fusion` / `WndFusion` / `FusionCharges` / `FusionRules`）
已整体移除：融合机会、升级发放、红包开出、状态栏图标、游戏菜单按钮、调试入口、
以及 `Item.fusedItems` 和各装备的融合 proc 合并全部删除。

原来的融合属性字段改名成 DIY 专用：
`fusionMin/fusionMax` → `diyMin/diyMax`（`KindOfWeapon`，存档键 `kw_diy_min/max`），
`fusionDRMin/fusionDRMax` → `diyDRMin/diyDRMax`（`Armor`，存档键 `diy_dr_min/max`）。

白帝圣剑 / 前线旗 / 莫雷洛 / 拉莱耶 / 幻影之书的被动现在直接看主手武器 +
`Diy.equippedItemProvides()`（DIY 特性），不再依赖融合。
